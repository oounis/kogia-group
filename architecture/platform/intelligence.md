# Kogia Intelligence

> **AI is infrastructure, not the company.**

Kogia does not sell "an AI". Intelligence is a capability that lives inside every
division.

```
KOGIA INTELLIGENCE
├── Discovery          ├── Automation
├── Recommendations    ├── Assistance
├── Matching           ├── Analysis
├── Personalization    └── Decision Support
```

## What it looks like in each division

| Division | What Intelligence does |
|---|---|
| Education | *"Darine is comfortable with addition but struggles with number decomposition."* |
| Skills | *"Your profile matches 17 new opportunities."* |
| Play | *"Your reasoning challenges should become slightly harder."* |
| Business | Reads an uploaded document, extracts the parties and dates, files it |
| Group | *"HVAC registrations from Tunisia rose 31% this month."* |

## The design rule: invisible, not conversational

**Not** a chat bubble in the corner saying *"Hello! How may I assist you?"* — that is
now ordinary, and it puts the work back on the user.

Intelligence should appear as **an answer already prepared**, inside the screen the
person is already looking at.

## Constraints

1. **Explainable where it affects a person.** A match score, a skill verification or
   a learning judgement must show its components.
2. **Never the sole source of a claim about a human.** See
   [Kogia Passport](kogia-passport.md).
3. **A model is not evidence.** In [Skills](../divisions/skills.md), proof comes from
   assessments, employers and completed work. Intelligence organises that evidence —
   it does not manufacture it.
4. **Cost is a design constraint.** Per-user AI cost must be known before a feature
   ships, or the unit economics are invisible.

## State

**Not built.** Used today only through ordinary tooling. Becomes real infrastructure
when [Opportunity Radar](../divisions/skills.md) or document intelligence in
[Kogia Office](../divisions/business.md) is built — whichever comes first.
